## 알려진 문제·주의
- Instagram 계정이 비즈니스 포트폴리오에서 빠지면 게시가 'Object ... does not exist' 오류로 거부됨 → 포트폴리오에 계정 재연결 + 시스템 사용자 reels-uploader에 콘텐츠·인사이트 권한 부여 (11-18 원인 불명으로 한 번 발생)
- PC 예약 작업이 Claude 설정 폴더(~/.claude)에 잠금 파일을 쓰면 승인 창이 떠서 무인 실행이 멈춤 → 11-18 잠금을 작업 폴더 private/ 로 옮김. 그러나 11-19 확인 결과 진짜 원인은 예약 작업의 권한 모드('승인 요청')였음 — 잠금 위치와 관계없이 첫 PowerShell 명령에서 멈춤. 앱 기록상 '성공'으로 보이지만 실제로는 중단됨
- 예약 작업이 기본 모델(Fable)로 돌던 것 → 11-20부터 Opus로 실행 확인
- 예약 작업의 새 실행은 작업 설정의 권한 모드로 시작됨. 열린 세션의 모드를 바꿔도 다음 실행에는 이어지지 않음 (11-20·11-21 확인)
- 예약 작업을 Claude가 직접 '지금 실행'하는 것은 자동 승인에서 막힘 → 다시 돌려야 하면 사용자가 Run now 하거나 Claude가 같은 점검을 대화에서 직접 수행
- 같은 폴더에서 대화 세션과 예약 작업이 동시에 일하면, 한쪽의 커밋에 다른 쪽의 작업 중 파일이 섞여 들어갈 수 있음 (11-19 발생, 테스트가 깨진 중간본이 4분간 올라갔다가 바로 수정). 커밋할 때는 `git add -A` 대신 자기가 고친 파일만 지정하고, 대화 세션도 잠금 파일을 확인할 것
- 글을 쓴 뒤 추가 신고로 그 달 건수가 늘 수 있음 → 영상은 글의 건수를 기준으로 표시 (11-19). 글 자체는 작성 시점 수치 그대로이며 하단에 수집 기준일 표기
- 신고가(기존 최고가 경신)는 수집 시작(2025년 10월) 이후 거래와만 비교한 값 → 11-16부터 글 하단에 기준을 밝히고, '역대 최고' 표현은 자동 검사로 차단
- 단지 글 작성기는 다른 면적의 거래 건수를 모름(facts에는 주력 면적만) → '주력 면적에 몰렸다·나머지는 몇 건 안 된다' 같은 짐작이 반복됨. 11-24 지침에 금지 명시, 2차 검수가 표와 대조해 잡음
- 11-24 이전 글 34편 본문에 '신고 기한·시차로 수치가 늘 수 있다' 문장이 하단 주석과 중복으로 남아 있음 (틀린 내용은 아니라 그대로 둠)
- 강서구 거래 최다 단지가 원자료에 '(50-5)'처럼 지번으로만 표기되는 경우가 있음 (원자료 그대로)
- YouTube 채널 하루 업로드 한도를 넘으면 업로드 실패 → 다음 실행에서 자동 재시도

- 반려 글: 2차 검수가 조사·수치 해석 오류를 잡아 반려 (정상 동작). 반려된 구는 다음 실행에서 다시 작성
- 영상 파일(mp4)은 만든 날의 배포에만 들어감 → Instagram·TikTok은 최근 영상만 게시 가능
- TikTok 예약 작업은 이 PC가 꺼져 있으면 다음 앱 실행 시 동작
- 옛 공개 저장소 기록에 폐기된 공공데이터 키가 남아 있음 (재발급 완료, 무효)
